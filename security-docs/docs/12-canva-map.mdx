## Texto corto reutilizable

### Problema

```text
La aplicacion rechaza ataques, pero no deja evidencia suficiente para detectarlos, investigarlos o responder.
```

### Causa raiz

```text
El backend no tenia un pipeline de auditoria: no habia eventos persistidos, correlation ID, severidad ni alertas por patrones.
```

### Solucion

```text
La rama fixed registra eventos en SQL Server, genera alertas internas y expone endpoints protegidos para investigacion.
```

### Conclusiones

```text
Bloquear protege el recurso inmediato. Observar protege la capacidad de respuesta.
```

## Graficos recomendados

1. Flujo vulnerable:

```text
Ataque -> 401/403 -> Sin evento -> Sin alerta -> Sin investigacion
```

2. Flujo corregido:

```text
Ataque -> 401/403 -> SecurityEvent -> SecurityAlert -> Investigacion
```

3. Tabla comparativa:

| Caso | main/master | fixed |
|---|---|---|
| Login fallido x5 | Sin evidencia | Eventos + alerta |
| Acceso admin denegado | Sin rastro | AccessDenied |
| Expediente ajeno | Sin trazabilidad | StudentRecordAccessDenied |
